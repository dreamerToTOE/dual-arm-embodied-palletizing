# R2-B 遮挡/丢帧预测比较

本比较只使用 physical04 的真实检测缺口。未使用刚体真值作为预测输入；Cube 真值仅用于离线评分。预测器均为因果形式，并随丢帧年龄增加而增大不确定性；接触与遮挡的原因在缺少独立接触观测时保持 ambiguous。

## 真实 dropout

共 51 帧、44 帧检测（检测率 `86.3%`）。丢帧区间为 `58.133–68.133 s`（10.0 s）、`70.133–72.133 s`（2.0 s）和 `74.133–76.133 s`（2.0 s）。这不是固定帧率声明，而是本 episode 的实际时间线。

## 三种因果策略

| 策略 | authored cy=360 平均/ P95 | cy=341 离线比较平均/ P95 | 约束 |
|---|---:|---:|---|
| P0 last valid visual | `.147 / .309 m` | `.143 / .301 m` | 保持上一有效视觉，误差随时间增长 |
| P1 visual velocity | `.459 / .998 m` | `.435 / .972 m` | 仅由历史视觉速度外推，长缺口不稳定 |
| P2 TCP propagation | `.130 / .163 m` | `.099 / .129 m` | 仅在双吸盘状态同时为真时评分；仍是有限支持 |

三者均为 7 个 gap samples，最长 gap 为 10 s。P2 使用实际 TCP 位移，附着门控只使用 trace 中的双吸盘状态；没有用 Cube 刚体 oracle，也没有把 PhysX 接触报告伪装成独立力传感器。由于本 episode 在 attachment/compaction 附近已出现观测缺口，P2 的“较好”只说明该段 trace 的条件性结果，不代表可迁移的恢复成功。

## 控制含义

当前最小可审计策略是 P0 作为安全基线，P1 仅作比较，P2 只有在独立附着证据成立时才可短时使用；出现长时间无视觉时不能自行判定是接触、遮挡或卡死。完整恢复/自适应 handoff 仍需主开发会话先修复 contact-state observability，并另行做 bounded physical validation。
