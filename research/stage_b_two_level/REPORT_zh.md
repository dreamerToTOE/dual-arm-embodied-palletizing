# 双臂码垛两级规划 CPU 可行性研究

## 研究结论

**总判定：INCONCLUSIVE。** 在本次有限的条件运动学模型和场景中，换序列、换臂都有用，但简单规则与穷举候选的通过数相同，尚未证明两级候选规划比规则有优势，也没有找到必须通过下层失败反馈才能改变上层序列的反例。虚拟吸附、动作原语和有限路径搜索仍限制对完整 Stage B 的判断。建议暂不将两级规划必要性作为已经成立的论文结论；先补全动作和验证，再扩大独立场景比较。按任务条件，本次不生成面向导师的 Word 提案。

| 决策门 | 结果 | 证据与边界 |
|---|---|---|
| Level 1 | `L1_SIMPLE_RULE_SUFFICIENT`，仅限本候选集 | 固定直插在 ±4°、±6° 失败，虚拟抓持后的抬升转向序列通过；偏航规则在本样本选到相同通过结果。该规则经过探索性结果启发，没有独立测试集。 |
| Level 2 | `L2_SIMPLE_RULE_SUFFICIENT`，仅限本候选集 | 侧壁和相邻货物场景中，另一臂可完成所建模路径；简单位置/占用规则在本样本也选择了通过的配置。没有证明其他构型或轨迹不可能。 |
| 两级交互 | 未证明 | 四个组合场景同时需要 correct 和右臂，但规则直接选中该组合；未观察到下层反馈迫使上层改选序列的具体案例。 |
| 规则 | 本样本内足够，泛化未知 | 与 M2 相同的 18/19 条件通过，不代表在未测场景也足够。 |

## 方法及有效性范围

继续使用原有 120 mm Cube、机器人及吸具、桌面和三面车厢壁碰撞模型；原车厢内部宽度约 606 mm，未按探索建议缩窄几何。保留 3 mm pre-contact 与 0.005 rad 最大关节插值步长等原阈值。以原始参考配置及其派生位姿为起点；这些是 Stage A 交接的离线假设，未证明物理可达。后排占用在场景元数据中记录先前放置次序，已放置 Cube 作为静态障碍保留。前排目标只在三处后排占用后评估；另设一例未完成后排的顺序负对照，在任何规划前拒绝。

候选序列仅包括 direct（接近、虚拟附着、17 mm 插入、释放及撤离）和 correct（虚拟附着、抬升 40 mm、调整偏航、放置、插入及撤离）。候选配置为左右臂及 1/2 mm 虚拟附着间隙；这不是经过验证的不同吸附位置或物理接触。接近规划纳入已放置 Cube，每个候选重验起始 pre-contact 路径及后续采样运动；机器人对场景使用 MoveIt 碰撞检查，活动 Cube 对桌面、壁和占用 Cube 使用 FCL。局部笛卡尔路径使用连续 IK 与固定采样；不是连续碰撞证明。每臂每种子仅尝试一条接近/对齐方案，因此拒绝只说明已评估路径失败，不能证明整个场景不可解。

M0 固定左臂、direct、1 mm；M1 在绝对偏航超过由原 3 mm 门限推导的 2.9416° 时选择 correct，并在目标 y ≤ −0.20 m 或已有后排占用时选右臂，否则选左臂；M2 穷举可用的左右臂、序列和两种间隙，通过完整已建模路径的候选优先。M1 使用的动作库是 M2 的子集，几何、碰撞与最终验收相同。规则由已有几何知识及探索结果设计，属于样本内比较，并非事先固定的盲测。

## 场景和结果

20 个场景：7 个 0°/±2°/±4°/±6° 偏航、4 个 ±Y 近壁、3 个合法后排占用、1 个后排完成后的前排、1 个禁止顺序负对照，以及 4 个偏航与近壁或占用组合。随机种子 28、29、30 各运行一次；种子控制 pre-contact IK 种子和 OMPL，后续局部轨迹是确定性的。三次各自得到相同的场景级结论。19 个合法场景中 M0 为 **7/19**，M1 为 **18/19**，M2 为 **18/19**；禁止顺序 1 例不计入分母，三个方法均拒绝。以下为种子 28，其他种子相同：

| 场景 | M0 | M1 | M2 | M2 选中 |
|---|---|---|---|---|
| yaw 0、−2、+2 | 3/3 通过 | 3/3 通过 | 3/3 通过 | 左臂 direct |
| yaw −4、+4、−6、+6 | 0/4 | 4/4 | 4/4 | 左臂 correct |
| 负 Y 近壁 −0.235、−0.220 m | 0/2 | 2/2 | 2/2 | 右臂 direct |
| 正 Y 近壁 +0.220、+0.235 m | 2/2 | 2/2 | 2/2 | 左臂 direct |
| 后排已放 0、1、2 个 | 1/3 | 2/3 | 2/3 | 0 个左臂 direct；1 个右臂 direct；2 个两臂接近均拒绝，M2 判为 INCONCLUSIVE |
| 后排完成后的前排 | 通过 | 通过 | 通过 | 左臂 direct；规则选择右臂也通过 |
| 偏航 ±4° 与负 Y 近壁 | 0/2 | 2/2 | 2/2 | 右臂 correct |
| 偏航 ±4° 与一个后排邻位 | 0/2 | 2/2 | 2/2 | 右臂 correct |
| 未完成后排便放前排 | 顺序拒绝 | 顺序拒绝 | 顺序拒绝 | 未规划 |

每个种子运行 38 次手臂 pre-contact，其中 20 次通过、18 次拒绝；对通过的手臂执行 80 个完整候选，64 通过、16 在插入时 Cube/环境碰撞而拒绝。每个合法场景实际评估 0、4 或 8 个下层候选。日志包含 IK 尝试数、采样数和后段关节路径长度；FCL 检查总次数未计数。

另外为 M0、M1、M2 分别重新执行从 pre-contact 到候选检查的计时，三个方法均使用 8 个并发场景 worker，每个场景内的候选串行评估；在三个种子间轮换方法执行次序。下表每项含 19 场景 × 3 种子共 57 次，其中包括失败及未能判断的场景。耗时包含各候选进程启动和日志写入，不含场景文件生成；它们是这台机器上的墙钟测量，其他负载未被完全控制。逐例结果与前述实验相同。

|---|---:|---:|---:|---:|---:|
| M0 | 21 | 0.597 s | 0.680 s | 57 | 33 |

本样本中穷举开销更大而未提高通过数；此结果不证明任何优化后的两级算法的性能。计时结果与日志位于 `evidence/timing_methods/`，分别使用相同的场景和碰撞验收。

首次探索性运行 `evidence/study_20261104/` 未加载 FR3 碰撞网格，**整体无效，不纳入任何结论**。之后启用参考 ROS 描述包，运行器将网格加载错误作为错误终止；`occupancy_seed_28`、`occupancy_seed_29`、`occupancy_seed_30` 是包含货物的接近规划正式数据。其他完整网格运行是接近路径尚未考虑占用的中间版本。结果中的路径和时间为本机记录，所有配置、日志、失败前缀及输出都保留；机器人模型和网格哈希记录在 `evidence/reference/`。

## 最小缺口与后续验证

最小的离线缺口是：在已放置 Cube 和全部原碰撞几何存在的场景中，针对同一操作枚举多个有效 pre-contact IK 与完整进退轨迹，并能把失败原因反馈给上层；还需具有物理意义、可验证的替代吸附位置/重抓原语。用独立场景和事先固定的规则复测，优先寻找「同一序列的候选全部失败，另一序列成功」的合法反例，并独立计量各方法端到端耗时与碰撞检查次数。增加狭窄车厢前，应另行确认与用户要求的既有几何约束兼容，不能通过人为堵死任务制造优势。

物理阶段全部延期：主开发需先验证清醒状态支撑反力等所需观测，再验证吸附建立、带载保持、放置释放及可执行换臂/重抓技能，之后才可进行受控接触与恢复实验。离线碰撞接近不是物理卡滞，条件规划通过不是物理恢复成功。本研究没有启动 Isaac Sim、GPU 物理、RL 或实际控制。

## 复现

在研究工作树中，使用 ROS Humble/MoveIt、FCL、OMPL 和含 FR3 碰撞网格的描述包；先核对 `evidence/reference/fr3_collision_meshes_sha256.json`。参考 URDF/SRDF 已保存在同目录。ROS domain 应在执行前检查空闲情况；示例 182 不保证任意环境空闲。输出目录必须不存在。以下只运行离线 CPU 规划，不连接控制器：

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu2004/lmy/dual-arm-embodied-palletizing/ros_ws/install/setup.bash
cmake -S research/stage_b_two_level -B /tmp/stage_b_two_level_rebuild -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/stage_b_two_level_rebuild -j4
python3 research/stage_b_two_level/run_study.py /tmp/stage_b_two_level_rebuild \
  research/stage_b_two_level/evidence/reference/robot.urdf \
  research/stage_b_two_level/evidence/reference/robot.srdf \
  research/stage_b_two_level/evidence/new_seed28 28
python3 research/stage_b_two_level/time_methods.py /tmp/stage_b_two_level_rebuild \
  research/stage_b_two_level/evidence/reference/robot.urdf \
  research/stage_b_two_level/evidence/reference/robot.srdf \
  research/stage_b_two_level/evidence/new_timing
```

运行机有 16 个逻辑 CPU、约 46 GiB 内存，试验使用 8 worker；因机器负载及 OMPL 实现不同，时间和个别路径可能变化。`results.json` 记录逐场景结果、候选、模型哈希、随机种子与失败阶段。
