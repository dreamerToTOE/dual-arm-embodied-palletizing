# Task 03 — B-A-C 放置可执行性

## 状态

✅ **已完成 — 已验证“箱体几何可放，但二指夹爪无法完成垂直插入”**

Task 02 已建立参数化 Placement Skill。Task 03 正式验证论文中的核心问题：

> **目标箱 A 的几何体能够放入目标空位，并不代表携带 A 的机械臂夹爪也能完成插入、释放和退出。**

---

## 1. 核心实验场景

目标箱 A：

```text
A size   = 30 × 30 × 30 mm
A target = (0.65, -0.15, 0.065) m
Yaw      = 0
```

邻箱 B、C 沿世界 Y 方向位于 A 两侧：

```text
B size   = 30 × 30 × 30 mm
B center = (0.65, -0.115, 0.065) m

C size   = 30 × 30 × 30 mm
C center = (0.65, -0.185, 0.065) m
```

B、C 内侧净间距：

```text
d_BC = 40 mm
```

A 沿 Y 方向宽度：

```text
w_A = 30 mm
```

因此只考虑箱体几何：

```text
d_BC > w_A
40 mm > 30 mm
```

A 本体可以放入，左右各约有 5 mm 几何间隙。

---

## 2. 与论文条件的对应

只考虑目标箱体本体时：

```text
d_BC >= w_A
```

只能说明 A 在几何上有空间。

机器人实际可执行条件还需要考虑夹爪外包络和安全间隙：

```text
d_BC >= w_A + 2 t_g + 2 delta
```

其中：

```text
t_g   = 单侧夹爪 / 手指相对箱体的额外占用厚度
delta = 安全间隙
```

这里影响密集放置的不是“夹爪长度”本身，而是夹爪在插入方向上的横向扫掠包络。


## 4. 第一轮问题：MoveIt 漏检夹爪碰撞

第一轮曾出现：

```text
C_insert = PASS
Cartesian fraction = 1.0000
```

但 Isaac 中真实 finger 已与 B/C 发生碰撞。

根本原因是规划 RobotState 只显式写入 `fr3_arm` 七个关节，没有同步：

```text
fr3_finger_joint1
fr3_finger_joint2
```

Isaac 抓取阶段实际保持：

```text
finger1 = 0.014
finger2 = 0.014
```

而 MoveIt 使用了默认 finger state，导致规划碰撞几何与真实执行不一致。

修复方式：在携物规划阶段显式将 finger joint 状态写入 MoveIt RobotState；C_reach / C_insert 使用闭合状态，C_retreat 使用张开状态。

该问题详细记录在：

```text
docs/KEY_ISSUES.md
```

---

## 5. 最终验证结果

修正 MoveIt 夹爪状态后，在同一 B-A-C 场景重新运行，用户确认：

```text
C_insert 报错 / 判定失败
```

同时 Isaac 中观察到二指夹爪在继续垂直下降时会与 B/C 发生真实几何干涉。

因此最终验证成立：

```text
A 本体几何上可放入 40 mm 空位
但携带 A 的 FR3 二指夹爪无法执行该垂直插入
```

即：

```text
几何可放置 ≠ 机器人可执行放置
```

Task 03 的核心验收目标正式完成。

## 6. 工程与论文意义

Task 03 说明码垛规划不能只输出箱体中心位姿，还必须考虑：

```text
夹爪尺寸 / 外包络
抓取方向
插入方向
扫掠体碰撞
释放空间
退出空间
```

如果采用二指夹爪并坚持竖直侧夹插入，则密集码垛时最终箱体间距会受到夹爪横向包络限制。

因此后续问题不应简单理解为“再给箱体留更大间距”，而应转化为放置策略选择问题，例如：

```text
调整放置顺序
改变抓取 / 插入方向
释放后进行推挤 / 紧凑化
切换更适合密集码垛的吸盘式末端
```

---

## 7. 与下一阶段的衔接

原 Task 04 规划为“放置顺序调整”。Task 03 的结果表明，仅调整顺序不一定能从根本上解决所有密集放置问题：如果最终间距小于二指夹爪所需横向扫掠空间，某一个箱体仍可能无法按竖直侧夹方式直接放入。

因此下一阶段应进一步研究“放置策略调整”，在顺序、抓取方式、插入方向、推挤紧凑化或吸盘抓取之间选择可执行方案。
